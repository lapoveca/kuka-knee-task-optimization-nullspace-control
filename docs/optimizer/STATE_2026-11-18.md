## 4. Active optimizer pipeline

```text
generate_global_placements.py
  -> screen_joint_proposals.py
  -> promote_screened_designs.py
  -> run_joint_design_eval.py
       -> evaluate_task_mounts.py
       -> audit_task_mount_run.py
  -> make_optimizer_report.py
```

Generator: constructs femur placements and paired attachment designs, enforces configured arm quotas/domain restrictions, and applies a necessary outer-reach rejection.

Screener: bounded multi-seed pointwise IK at 19 distinct selected task poses. Initial-pose failure is classified separately. It does not establish connected-path feasibility.

Promoter: selects pointwise passes using greedy max-min diversity. The latest implementation includes attachment-family/azimuth information. This is not a global optimizer or performance ranking.

Whole-task evaluator: multi-seed initial IK, continuation/beam search, piecewise-linear joint edges, tracking/velocity checks, and nominal zero-bias task-torque capability. The orchestration records candidate checkpoints and invokes a saved-path audit.

Auditor: separately checks saved paths and recomputes metrics using shared robot/task mathematics. It is not mathematically independent of all production code.

Reporter: figures for coverage, capability over time/groups, limiting joints, joint trajectories, and candidate comparisons. Verify dimensionless capability labels and avoid inferring physical capacity from them.

## 5. Transform conventions

`X_AB` maps B-frame coordinates into A-frame coordinates.

- B: robot base, `lbr_link_0`.
- F: fixed femur reference, OpenSim `femur_base`.
- T: OpenSim body named exactly `tibia`.
- E: robot frame `lbr_link_ee`.
- `X_FT(t)`: prescribed tibia motion relative to F.
- `X_BF`: one constant placement for a complete candidate task.
- `X_TE`: robot EE pose in T.
- `A = X_ET = inverse(X_TE)`.

Authoritative relations:

```text
X_BT_required(t) = X_BF @ X_FT(t)
X_BE_required(t) = X_BT_required(t) @ X_TE
X_BT_attached(q) = FK_E(q) @ A
```

Robot-informed construction used by the current generator:

```text
X_BF = FK_E(q0) @ A_reference @ inverse(X_FT(t0))
```

Earlier handover text and generated documents contain incorrect alternative formulas and reversed transform descriptions. They must not override these relations.

## 8. Placement domain and sampling limitations

The placement point is the F origin in B, not the EE or tibia origin. The domain is a configurable cross-shaped collection of four rectangular XY arms extruded over a declared z range, with a central exclusion region. Lower z bounds are exclusive.

Current pilot: two placements per enabled arm, 8 placements total, nine designs each. An explicit `--allow-placement-count-override` was added because the standard domain configuration requests ten placements per arm. Domain metadata may still report the configured count while the CLI override supplies the actual requested count; report both explicitly.

Current generator still constructs placements using the axial mount and stores the constructing q0 for every mount. This gives axial initial reachability by construction. Calling it a reference parameterization does not remove the sampling/seed bias. It also rejects a placement if any catalog mount violates the outer-reach filter, which is a deliberate but restrictive acceptance condition.

Before the final study, choose and document either independent domain sampling with equal treatment of all nine mounts, or a clearly declared feasibility-conditioned construction policy. Equal candidate importance does not imply an unbiased spatial sample.

## 11. Loading corrections and current state

The old 0.35 m value served as both mount position and distal force application point. User explicitly clarified that the load application point moves with the selected attachment. It is not an independent fixed 0.35 m biomechanical location.

The initial attachment-origin implementation retained the old force magnitude 19.417475761968834 N. This correctly shifted wrench reference points but underloaded the target knee moment:

- axial: 9.223301 Nm generalized VV;
- peripheral: 8.640777 Nm generalized VV;
- intended target: 10 Nm.

A second defect returned the same positive force for both signed cases. This was corrected with explicit case_signs [-1,1]. All nine signed-case tests passed. Symmetric zero-bias torque limits can hide this defect in lambda, but that does not make the semantics acceptable.

Correct wrench reference shift at zero direct contact couple:

```text
W_T = [F_T ; p_contact_T cross F_T]
```

Correct generalized VV moment uses anatomical virtual work:

```text
tau_VV = (v_T + omega_T cross p_contact_T).T @ F_T
```

Do not calculate required force as 10 divided by the attachment's x coordinate: T is offset from the VV axis.

Read-only OpenSim diagnostic checked model hash, reproduced saved poses, estimated VV derivatives, computed the minimum-norm force at the first sample, and verified it across all 521 saved postures. All nine constant forces preserve 10 Nm to about 3.6e-11 Nm or better in this diagnostic.

- peripheral 00/04: 22.471910 N;
- peripheral 01/03/05/07: 22.446421 N;
- peripheral 02/06: 22.421017 N.

Some normalized forces contain an x_T component. Force direction is not constrained to EE +z. Other generalized-coordinate reactions are not constrained to zero.
